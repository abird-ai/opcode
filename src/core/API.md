# core API contract (frozen for M2)

All files include `opcode.inc` and then `core/core.inc`. ABI: rdi, rsi, rdx, rcx,
r8, r9; return rax (+rdx); PROLOGUE/EPILOGUE; 16-byte aligned calls.

## src/core/messages.s

Ownership: every string passed to a `msg_*`/`tr_*` function is **copied** with
`mem_alloc` and owned by the transcript; `tr_free` releases everything.

```
tr_init(tr)
tr_free(tr)
tr_push(tr, Msg*) -> Msg*
tr_len(tr) -> n
tr_msg(tr, i) -> Msg* | 0
tr_clear(tr)                          # frees messages, keeps the transcript usable

msg_new(role) -> Msg*                 # blocks VEC allocated, stop = SR_PENDING
msg_add_block(msg, type, ptr, len) -> Block*
    # text/think: copies ptr/len; returns the Block
msg_add_toolcall(msg, id cstr, name cstr, args cstr) -> Block*
    # tool call args are stored as a cstr copy; returns the BT_TOOLCALL block
msg_set_usage(msg, Usage*)            # copies the Usage struct
msg_set_call_id(msg, id cstr)         # for MR_TOOL_RESULT: copies the tool_call id
msg_call_id(msg) -> cstr | 0
msg_toolcalls(msg) -> n               # count of BT_TOOLCALL blocks
msg_toolcall(msg, i) -> TC*           # i-th tool call pointer
```

`Transcript` layout and `Msg`/`Block`/`TC`/`Usage` offsets: `core/core.inc`.

## src/core/tools.s

```
tools_init()                           # register all built-ins (read, bash, edit, write,
                                       # ls, find, grep); also calls search_tools_init()
tools_add(TL*)                         # registry append (returns 0|-ENOSPC)
tools_count() -> n
tools_at(i) -> TL*
tools_find(name cstr) -> TL* | 0
tools_active() -> VEC*                 # all registered tools (M2)
tool_validate(name cstr, args cstr) -> 0 | -EINVAL
tool_err(job, msg)                     # writes an error result and completes
tool_done(job)                         # marks JS_DONE (idempotent)
truncate_head(sb, max_lines, max_bytes, path_hint cstr)
```

Job result text lives in `job->J_out` (an SB owned by the caller). `TL_exec`
either completes synchronously (`tool_done`) or launches a child and returns;
the agent loop watches `J_fd` and calls `TL_finish` at EOF. `J_pid` 0 means
in-process. `J_deadline_ms` is an **absolute** CLOCK_MONOTONIC millisecond value
(0 = no deadline); the loop kills the child when it passes, sets `JF_TIMEOUT`
on the job, and `TL_finish` reports `[timed out]`. `os_spawn` puts each child
in its own process group; kill paths use `os_kill_group`.

## src/tools/read.s / bash.s

- `read_exec(job)`: args `{path, offset?, limit?}`; `limit` caps the returned
  lines (default and hard maximum 2000) and the result head-truncates at
  2000 lines / 50 KB with a correct `offset=` continuation hint; errors are
  results with `tool_err`.
- `bash_exec(job)`: args `{command, timeout?}`; `sh -lc command`, stdout+stderr
  captured (pipe), timeout default 120 s; `TL_finish` reaps the child, appends the
  exit code on its own line, completes. Requires Layer 0
  `os_spawn/os_pipe/os_wait/os_kill_group` (src/plat/linux/proc.s).

## src/core/agent.s

```
agent_config:  globals set by the app
    g_agent_provider (cstr), g_agent_model (cstr), g_agent_base (cstr override),
    g_agent_system (cstr), g_agent_replay (cstr file), g_agent_max_tokens (u32),
    g_agent_verbose (u32)
agent_run(prompt cstr) -> exit code    # print mode: run to completion, stream text
agent_abort()
```
`agent_run` drives the state machine with the watch table + loop_poll, streams
assistant text to stdout, executes tools, and returns 0 on a completed answer,
1 on error. `agent_abort` sets a cancellation request; the next
`agent_step` tears the in-flight transport down and emits `SE_DONE` with
`SR_ABORTED` (5) to the UI hook exactly once (the turn's done flag guards
against a provider `PV_finish` `SE_DONE`), then leaves the state at `AS_DONE`
(see the exit-code contract below).

# M3 additions (frozen)

## Session format (JSONL, serde-native, our own schema)

One JSON object per line, snake_case keys, tagged by `"type"`. All timestamps are
Unix milliseconds (integers). File name: `<unix_ms>_<id8>.jsonl`.
Location: `$OPCODE_SESSION_DIR`, else config `session_dir`, else
`$XDG_DATA_HOME/opcode/sessions/--<sanitized-cwd>--/` (sanitize `/` and `\\` to `-`).

```jsonc
{"type":"session","schema_version":1,"id":"a1b2c3d4","timestamp":1759000000000,"cwd":"/home/u/proj"}
{"type":"model_change","provider":"anthropic","model":"claude-sonnet-4-5"}
{"type":"message","id":"1a2b3c4d","parent_id":null,"message":{
   "role":"user","timestamp":1759000000001,"content":[{"type":"text","text":"hi"}]}}
{"type":"message","id":"...","parent_id":"1a2b3c4d","message":{
   "role":"assistant","timestamp":...,"stop_reason":"tool_use",
   "usage":{"input_tokens":10,"output_tokens":25,"cache_read":0,"cache_write":0,"total_tokens":35},
   "content":[{"type":"text","text":"..."},
              {"type":"thinking","thinking":"..."},
              {"type":"tool_use","id":"toolu_1","name":"bash","input":{"command":"echo hi"}}]}}
{"type":"message","id":"...","parent_id":"...","message":{
   "role":"tool_result","tool_call_id":"toolu_1","is_error":false,"timestamp":...,
   "content":[{"type":"text","text":"hi\n[exit 0]"}]}}
{"type":"custom","custom_type":"...","data":{...}}
```

- `parent_id` is the previous entry's id (linear chain in M3; the field is there for
  later branching).
- `schema_version` gates the load: a missing value is the legacy 1, a value greater
  than the current 1 refuses to load (naming both versions and "written by a newer
  opcode"), and older or equal values load unchanged. No migration hook is defined
  yet because no older format exists.
- `input` is inserted raw (valid JSON); `thinking` blocks are written but skipped on
  load into the live transcript (kept in the file).
- `content` for user/system/assistant is an array (system never enters a session).

## src/tools/edit.s and src/tools/write.s

- `edit`: `{path, edits:[{oldText,newText}]}`. All matches are located in the
  ORIGINAL text; each `oldText` must be unique and non-overlapping; apply right to
  left; preserve a UTF-8 BOM and CRLF line endings; write atomically (temp file in
  the same directory + `os_rename`); result text = `edited <path>: N replacement(s)`
  plus the unified diff (diff capped at 400 lines).
- `write`: `{path, content}`. Creates parent directories (`os_mkdir` recursively),
  writes atomically, result `wrote <path> (N bytes)`.
- Both are read-modify-write on one path; the loop already calls their `TL_exec`
  synchronously in tool-call order, so concurrent edits of the same path serialize.

# S2 additions (frozen)

Core plumbing for the live-UX stage: thinking level, usage/context
accessors, model switching, compaction surfacing and registry enumeration.
No new layer boundary is introduced: everything below lives in `src/core` or
the Anthropic adapter (`src/prov`, which already calls core).

## Thinking level

Thinking uses opcode's own monotonic scale (0..3):

```
off = 0   low = 1   medium = 2   high = 3      (core.inc: TH_OFF..TH_HIGH)
```

```
g_agent_thinking: .long     # active level; -1 = unset (agent_init applies config)
agent_set_thinking(esi level)          # clamp 0..3, store; no-op otherwise
agent_thinking() -> eax level          # 0 when unset/off
agent_thinking_name(esi level) -> rax cstr   # "off"/"low"/"medium"/"high"
agent_thinking_parse(rdi name) -> eax level | -1
```

The level is the **second** argument register (`esi`) because the C API it
mirrors carries an implicit agent pointer in `rdi`; callers must pass the level
in `esi`. `agent_thinking_name`/`agent_set_thinking` clamp out-of-range values
(the name getter maps negative/unknown to `"off"`).

- CLI: `--thinking off|low|medium|high` (`src/app/cli.s`, `CK_AGENT`). An
  invalid value is a usage error (exit 2).
- Config: `default_thinking` in `<config>/config.jsonc`, read through
  `config_default_thinking() -> cstr|0`. The CLI flag wins; with neither the
  value stays `off`.
- `agent_init` applies `config_default_thinking()` only when `g_agent_thinking`
  is still -1.

### Anthropic budget mapping (`src/prov/anthropic.s`)

The `thinking{type:"enabled",budget_tokens:N}` object is emitted only for a
model with `MDF_REASONING` and a non-off level:

| level  | desired budget |
|--------|----------------|
| off    | (no object)    |
| low    | 1024           |
| medium | 4096           |
| high   | 8192           |

The budget is clamped to `max_tokens - 1024` (so the API invariant
`budget_tokens < max_tokens` always holds) and the whole object is omitted when
the result would fall under 1024. The adapter reads `g_agent_thinking`.

## Usage / context accessors

```
agent_usage_totals(rdi out Usage*) -> 0
agent_model_ctx_window() -> eax
agent_transcript() -> Transcript*        # unchanged
```

`agent_usage_totals` zeroes `out`, sums `input`, `output`, `cache_read` and
`cache_write` over every `MR_ASSISTANT` message in the transcript, and sets
`USG_total = USG_input + USG_output`, the two token counters it owns; cache tokens
are reported separately and are **not** part of the total.
`agent_model_ctx_window` returns the active model descriptor's `MD_ctx_window`
(0 when no model is resolved).

## Model switching

```
agent_set_model(rsi id cstr) -> 0 | -EINVAL
```

The id is the **second** argument register (`rsi`), again mirroring the
implicit-agent C signature; pass `0` (or anything) in `rdi`. The id is resolved
through `catalog_find()` for the current provider (`a_md->MD_provider`, else
`g_agent_provider`, else `"openai"`). A `provider/model` form overrides the
provider prefix; an empty prefix or empty model is `-EINVAL`. On success
`a_md` is swapped and `a_pv`/`a_pvctx`/`a_key` are rebuilt in place for the new
provider (`max_tokens` = the `--max-tokens` flag, else the model's, else 4096).
An unknown model leaves the agent untouched and returns `-EINVAL`. The session
is never closed or reopened.

## Compaction surfacing and manual compaction

```
SE_COMPACT, 12                 # core.inc; a = tokens_before u32, b = kept u32
agent_compact() -> 0 | -EBUSY
```

`agent_compact` runs the same summarization path as the automatic
`compact_maybe_run` but ignores the `compact_needed` threshold; it refuses while
a turn is in flight. On success `compact_maybe_run`/`agent_compact` emit
`SE_COMPACT` to the UI hook (`g_agent_ui_fn`) *before* the session custom entry:
`a` is the estimated token count before compaction (`tokens_before`) and `b` is
the number of messages preserved (`before_n - cut`). The existing values of the
other `SE_*` constants are unchanged.

## Tool-execution record (`SE_TOOL_EXEC`)

```
SE_TOOL_EXEC, 13              # core.inc; rdx = &TE
TE_SIZE, 40                   # core.inc
```

When every tool of a batch has finished, `agent_tools_finished` emits one
`SE_TOOL_EXEC` per job to the UI hook, in job order, immediately after the
legacy `SE_TOOL_RESULT` (11, unchanged, `a=ptr b=len`). `rdx` points at a `TE`:
`{cstr id; cstr name; cstr args; ptr result; u64 result_len; u32 error; u32
duration_ms}`. `result`/`result_len` are the raw output bytes and are valid only
for the duration of the call (the UI copies what it needs); `name` is `"?"` for
an unknown tool; `error` is 1 when the job carried `JF_ERROR`; `duration_ms` is
measured from `CLOCK_MONOTONIC` at tool start (`J_started_ms`). An abort that
teardown-completes a tool batch emits the same records through
`agent_tools_finished`.

## Registry enumeration (`src/core/prompt.s`)

```
prompt_templates_init() -> 0                              # unchanged
prompt_templates_count() -> eax
prompt_templates_at(edi i) -> rax name cstr | 0
prompt_template_expand(name cstr, args cstr, out SB*) -> 0 | -ENOENT   # unchanged

skills_list() -> rax count
skills_at(edi i) -> rax name cstr | 0
skill_body(name rdi, out SB* rsi) -> 0 | -ENOENT | -EFBIG | -errno
```

- `prompt_templates_*` expose the file templates registered by
  `prompt_templates_init()` (call it first); names are borrowed until the next
  `prompt_templates_init()`.
- `skills_list()` frees any previous table and rescans `<config>/skills` and,
  when the cwd is trusted, `<cwd>/.opcode/skills`, reusing the existing
  `pc_skill_cb`/`pc_scan_dir` scanner and the `pc_skills_sort` order used by
  `prompt_build` (name-sorted). It returns the count; `skills_at` returns the
  i-th name (borrowed until the next scan).
- `skill_body` looks the name up in the table populated by `skills_list()` (no
  rescan, so a caller may hold the names), reads the skill file and appends its
  frontmatter-stripped body to `out`. A body over 256 KiB (`PC_SKILL_MAX`,
  matching opcode's skill-submit cap) is refused with `-EFBIG` and
  `out` is left unchanged.

`Usage`, `MD_ctx_window` and the `SE_*` offsets remain as documented in
`core/core.inc`.

# H2 hardening (core agent/compact/session)

## The agent is a process-global singleton (deliberate)

The agent is **not** an object: its state lives in file-global storage in
`src/core/agent.s` (`a_tr`, `a_msg`, `a_jobs`, `a_fd`, ...), the resolved
provider/model in `a_md`/`a_pv`/`a_pvctx`, the active session in
`g_agent_session`, and the configuration in the `g_agent_*` globals set by the
app. There is exactly **one agent per process** and it is **not reentrant**:
`agent_run`/`agent_submit` must not be called from an agent callback (UI hook,
tool `TL_finish`), and `agent_init` is a one-time process setup. Full `Agent*`
encapsulation is intentionally deferred (the CLI/TUI never needs two agents)
and recorded as accepted debt; callers that need two conversations must fork.
`g_agent_session` may be `0` (no persistence), in which case transcripts live
only in memory.

## Abort and exit-code contract

- `agent_abort()` is cooperative: it sets a flag. The next `agent_step` runs
  the teardown (kill+reap every running tool child, close the transport,
  answer any dangling `tool_use` with an `MF_ERROR` result), emits
  `SE_DONE`/`SR_ABORTED` once, and leaves `a_state == AS_DONE`. A run finished
  this way reports **exit code 0** from `agent_exit_code()` (the abort is a
  user action, not a failure); an actual failure (`agent_fail`) sets exit 1.
- Fatal `SIGINT`/`SIGTERM` in the print/JSON/RPC modes are installed by
  `src/app/main.s`: it points the platform `g_exit_hook` at
  `agent_sig_cleanup` and calls `os_sig_cleanup()` (the TUI installs its own
  terminal-restore hook later). The platform handler runs the hook
  (`agent_sig_cleanup` sets the abort flag, `SIGKILL`s and reaps each running
  tool group, closes its pipe, closes the active transport) and then
  re-raises the signal, so the process terminates with the truthful signal
  status: **128 + signum** (130 for `SIGINT`, 143 for `SIGTERM`). No tool child
  and no pipe fd survive Ctrl-C.
- `agent_sig_cleanup` is async-signal-safe: it allocates nothing and is also
  safe as the normal `os_exit` hook (the jobs/fd are then already idle).

## Compaction: recurrence, persistence, ownership

- `compact_maybe_run` is called from `agent_submit` (guarded by `agent_busy`)
  before every turn, not only once from `agent_init`, so a long-lived process
  (TUI, repeated prompts) stays bounded. It is a no-op below
  `compact_needed`.
- `compact_apply` frees each removed message completely: it untracks and frees
  every leaf (Msg, text, `ToolCall` + its id/name/args, `Usage`, `call_id`),
  frees the message's `M_blocks` VEC, and drops the `TR_msgs` entries. Repeated
  compaction therefore does not retain dropped text until `tr_free`.
- When `g_agent_session` is set, `compact_apply` appends the wrapped summary to
  the session as a real `MR_USER` message; the existing `"compaction"` custom
  entry follows. `session_load` honors that entry: on seeing
  `custom_type == "compaction"` it drops the first `data.first_kept` messages
  from the already-loaded prefix, moves the summary (the last loaded message)
  to the front, and keeps it plus the tail. `--continue`/`--resume` thus loads
  the compacted transcript and does not re-summarize the pre-compaction text.

## Session schema

`session_load` refuses a header whose `schema_version` is present but not a
JSON number (for example a quoted `"999"`: the value's `JT_NUM` type is
checked before `json_get_u64`), in addition to a numeric value greater than
`SESSION_SCHEMA` (1). A missing value is still the legacy 1.

## Provider dispatch

`<MD_api> -> PV*` is a single static table plus `prov_for_api(api)` in
`agent.s`; both `agent_init` and `agent_set_model` call it. Adding a wire API
is one table row (ADR-7); the table falls back to `prov_openai` for an unknown
or missing api.
